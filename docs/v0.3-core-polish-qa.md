## Evidence and method

- Shopify CLI development preview: `http://127.0.0.1:9292`, against unpublished Nami QA, theme `167179321404`, store `app-test-siv6djjk.myshopify.com`.
- Isolated headless Chromium using the installed Chrome executable and temporary Playwright installation; no browser framework added to Nami.
- Direct page/section screenshots at actual widths 390, 768 and 1440. Additional page-wide overflow checks at 320, 375, 430 and 1024.
- Existing merchant product/shop images only, selected in temporary QA templates outside the repository. No catalog edits, added stock imagery or fabricated endorsements.
- Local evidence directory: `../artifacts/nami-core-polish/` relative to the repository. Includes seven contact sheets, individual screenshots, `metrics.json`, `refresh.json`, `stress.json`, `counts.json`, `gate.json`, `cart-page-gate.json`, `extra.json` and `runtime.json`. Diagnostic scripts remain outside the distributed theme.
- Sparse products: 1/2/4 cards; collection cards: 1/2/3; Bento: 1–5 mixed tile counts, product/editorial/text and overlays. Hero: image/no image, short/medium/long copy, split/overlay and custom scheme. Full PDP, collection, cart and search pages reviewed rather than grading isolated fragments alone.

## Interactive regression

At 390/768/1440: homepage/sticky header; product variant/price/available purchase; sale/sold-out state; Add to Cart; drawer quantity increase/decrease, subtotal, note persistence, remove and empty cart; Checkout visibility and hit testing without activating checkout; predictive results, ArrowDown, Escape and no-results; native sort/filter/active-state clear; six sequential hotspot edge/adjacent opens, single-open state and Escape; comparison keyboard and direct pointer drag; sparse carousel controls and resize behavior.

Mobile menu Escape and focus restoration were exercised at 390. Cart-page native submissions were separately verified at all three widths for quantity increase/decrease, properties, note persistence, visible/unobscured Checkout and removal. Test contexts were separate from the user's QA browser cart and cleared after testing. Shopify's draft preview bar is external chrome; the CLI route does not inject that toolbar into Nami layout.

Rendered review required a second pass: an initial Hero colour-scheme comparison failed because Shopify supplies a scheme object; string normalization and CSS specificity were corrected. Early Bento sizing made desktop media too tall; bounded source-specific heights replaced it. A lazy collection image appeared blank in an early screenshot; waiting for image decode confirmed real imagery, not an empty theme surface.

## Validation and limits

Run before commit: `shopify theme check --path .` (85 files, zero offenses); `node scripts/validate-theme.cjs` (73 documents); hardening, upgrade (14 actual v0.2 saved documents), P0/P1, P2 and polish scripts; both JavaScript syntax checks; `git diff --check`; strict upload of the actual final repository to the exact unpublished QA theme, excluding the remote-only gift-card template. P2 and polish tests also run in CI.

No fresh manual Theme Editor coverage is claimed: Admin connection verification remains unavailable. Schema/preset validation is not a substitute for manual editor coverage. Native swatch metadata is absent from the available fixtures; no fresh native video/3D or app-block fixture coverage is claimed. Physical devices, Safari and Firefox were not tested in this pass. Known Shopify platform/preview request noise is recorded separately from uncaught theme errors.

Estimated merchant-quality readiness: approximately **80%**, a judgement rather than a measured completion percentage. Remaining B grades are not release-blocking regressions, but this pass does not authorize release.
