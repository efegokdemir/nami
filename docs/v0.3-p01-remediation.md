# v0.3 P0/P1 remediation

2 October 2026. Baseline: `7cbb73446d869aa0f504e240574c71e7874251dc`.
This report belongs to the remediation commit, not a release. No tag or release is authorized.

## Outcome

The reproduced P0 containment defects and P1 layout/accessibility defects were corrected through shared systems. Revised assessment: **A 0 / B 35 / C 10 / D 0; 50–75% merchant-quality ready**. B means usable with refinement, not premium or finished. The ten C sections remain substantive composition/polish work. No release recommendation is made.

## Shared changes and fixed defects

- `section-style` now supplies responsive spacing variables rather than fixed inline padding. CSS owns their application. Compact/standard/generous defaults are 28/56/78.4px desktop and 20/36.4/50.4px mobile. Adjacent Shopify section wrappers reduce the following section's top contribution by half; explicitly selected custom padding stays exact. Reading widths and alignment now operate instead of being defeated by ID-level max-width.
- Newsletter and Video media have bounded widths, shrinkable tracks and configured aspect ratios. Adjacent Video without copy uses a single track. Newsletter tablet composition no longer compresses text to 19px.
- Content/product grids use readable minimum tracks, responsive clamping and count-aware layouts. One-product grids are bounded to 420px; two-product grids to 864px, except intentional carousels. New merchandising presets use four desktop/two mobile products; saved selections remain supported. At 320px, content cards may correctly use one column instead of unreadable narrow tracks.
- Shared product-card CSS owns ratio, fit, radius, badges, text, swatches and actions. Quick Add occupies the media frame, appears on hover/focus on pointer devices and stays visible on touch. Existing forms, variant behavior and shared rendering remain intact. Full product titles remain in DOM; displayed titles are clamped to two lines.
- Sticky positioning belongs to the Shopify header wrapper. Transparent homepage headers require first-section media and become solid after the Hero. Actual scrolling verified no wrapper collapse or height jump. Tablet PDP uses balanced tracks; at 768px the information column is 334px rather than 237px.
- Hero and saved legacy Split hero render through one snippet. Legacy file/settings survive, but its duplicate preset is removed. Empty Hero is compact and text-first; irrelevant media/height/layout controls are conditional. Explicit long merchant content is not clipped or height-capped.
- Mobile native filters start-align compact fields and actions within a scrolling panel. Filtering and sorting preserve native URL state.
- Empty App area, Custom Liquid, marquee, tabs, collapsible rows and optional resource sections no longer create meaningless live surfaces or focusable empty controls. Editor guidance remains. Empty slideshow is text-first and has existing carousel navigation/focus semantics.
- Contact IDs include section identity; labels, email error association and error alerts are correct across two instances. Textarea is four rows and the form is bounded. Announcement rich text is no longer escaped into literal tags.
- Marquee is static by default. Its existing motion boolean is relabeled to express animation; animated mode always supplies hover/focus pause plus a persistent button. A rendered test found and fixed specificity overriding pause. Reduced motion and minimal motion remain static; repeated copies are inert. Hosted Video autoplay is gated and preserves controls when motion is disabled or playback fails.
- Template-bound main sections and recommendations have supported template restrictions; header/footer are group-restricted. Existing templates remain valid. Image with Text introductory fields always render before blocks rather than silently disappearing; saved duplicated intro content may need merchant review. Comparison inputs follow selected column count. Product-source precedence is labeled explicitly.
- Featured Product defaults to thumbnails with bounded media; saved explicit stacked galleries remain available. Timeline imagery becomes compact beside text, Icon list custom images are small, Gallery/collections adopt safer mobile defaults, text-only Bento avoids fixed empty rows, and Footer adapts to available visible blocks.
- Search and Blog use native pagination by 24; Collection pagination is retained.

## CSS and architecture removed/simplified

Deleted superseded product-card radius/fit/action rules from theme/overhaul CSS, fixed inline normal spacing, ineffective direct-section adjacency, legacy giant Hero min-heights, child-only sticky positioning and duplicate Split hero markup. The three existing stylesheet responsibilities remain; they were not merged for appearance. `assets/nami.js` commerce logic is unchanged. No sections, blocks, controls, catalog data or production-default imagery were added.

## QA and limits

- Five temporary fixture pages × seven widths: **35 states**, no reproduced page-wide overflow, Liquid error or live setup help. Native Collection/Search/Cart: another **21 states**, no page-wide overflow. Actual PDP was inspected/measured at all seven widths; 390/768/1440 screenshots retained. Home empty/long/overlay, legacy split, fixed media, stacked sections, no images/resources, one/many products, sold-out/sale/no-image/multi-variant cards were exercised.
- Theme Editor: Hero control visibility and section picker context were inspected, without saved edits. Cart/404/Article yielded zero homepage additions; only the modern Split hero preset appears. Other conditional fields are schema/strict-upload tested, not claims of manually clicking every field. Repeated initialization/reload is covered by runtime tests.
- Actual variant selection and Add to Cart increased the existing Powder cart item from one to two, and quantity decrease restored one. The original item/note were preserved. In-stock filter showed 11/14 products; ascending-price sorting retained the filter. Predictive search, arrow-key focus/Escape, mobile menu and native recommendations passed. No checkout/order, contact POST or newsletter subscription was submitted.
- Product external YouTube video renders a titled 16:9 frame: **744×418.5 desktop; 350×196.875 at 390**, replacing the old 350×150 frame. The embedded player controls loaded. This is not Shopify-hosted Video or a Model3D test. No available hosted-video/3D/native-swatch fixture was invented, and no app was installed. Arbitrary app blocks, physical devices, Safari (password access deliberately left unverified), Firefox, nested menus and virtual keyboards remain external coverage.
- Two Contact sections have unique IDs and correctly associated labels. Persistent marquee pause survives focus departure; reduced motion yields animation `none` and transform `none`. Header proof shows 69px desktop/65px mobile, top 0 while scrolled, and transparent-to-solid transition without height change.
- Search/Blog pagination implementation and upload are validated; real page-two testing is unavailable with 14 catalog products and no populated blog. Intrinsically tall/wide new images and extreme 100+ character product titles were not created. Existing ratios, long merchant headings/paragraphs and observed catalog titles were tested.

Local evidence is stored outside the theme at `../artifacts/nami-p01-remediation/`: final `metrics.json`, `native-metrics.json`, `header-proof.json`, viewport screenshots and commerce/editor captures. `initial-metrics.json` is an obsolete diagnostic, not final evidence. Fixtures deliberately reused existing wax imagery; no QA-store art direction or production demo imagery was added. Final repository upload restores generic homepage/header configuration and removes temporary fixture templates.
